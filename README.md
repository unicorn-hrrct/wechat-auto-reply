# 微信自动回复助手

**简体中文** | [English](README.en.md)

指定要自动回复的联系人，以及回复的内容；当该联系人发来消息时，程序自动替你回复。

```text
[10:23:45] 张三 发来消息: 在吗
[10:23:46] 已回复 张三: 我在忙，稍后回复你
```

## 特性

- **指定联系人与回复内容** —— 交互式挑选联系人或群聊，逐条设置回复内容，规则持久化到 `rules.json`
- **回复内容支持模板** —— 用 `{content}`、`{sender}`、`{time}` 让回复更自然
- **同一条消息只回复一次** —— 按控件 ID 去重，不会对同一条消息回两遍；对方发新消息仍会回复
- **不打断你** —— 使用独立聊天窗口监听，你可以照常用微信跟别人聊天，互不影响
- **不偷剪贴板** —— 发送前备份、发送后恢复你原来的剪贴板内容
- **不回复历史消息** —— 启动时先建立基线，只有之后新到的消息才会触发回复
- **可离线测试** —— 48 个测试不需要安装微信就能跑，方便你改动代码

## 快速开始

### 安装

```bat
git clone https://github.com/unicorn-hrrct/wechat-auto-reply.git
cd wechat-auto-reply
pip install -r requirements.txt
```

依赖只有两个：`uiautomation`（驱动微信界面）和 `pyperclip`（写入剪贴板用于发送）。装完可以跑一次依赖自检：

```bat
python check_deps.py
```

> **为什么不用 wxauto？**
> 网上教程普遍推荐的 `wxauto` 曾经是这类需求的首选，但它目前**已经从 PyPI 下架**（`pip install wxauto` 会直接报 `No matching distribution found`），只剩 GitHub 源码。本项目的 `wechat_uia.py` 用底层同样的 `uiautomation` 自己实现了收发消息，不依赖任何已下架的包，安装不会踩坑。

### 一、先自检（可选但推荐）

```bat
python auto_reply.py --check
```

确认能检测到微信主窗口。如果提示找不到，请对照输出的两类原因排查。

### 二、交互式配置（最常用）

```bat
python auto_reply.py
```

程序会引导你完成三步：

1. **连接微信** —— 自动找到并激活已登录的微信窗口
2. **配置规则** —— 列出你所有的微信会话，输入序号（支持 `1,3`、`1 3`、`1-3`，也可直接输入名字），然后逐一输入回复内容
3. **启动监听** —— 为每个联系人打开独立聊天窗口并开始轮询

配置完的规则会自动保存到 `rules.json`，下次启动会询问是否直接复用。

### 三、直接指定（不交互）

```bat
python auto_reply.py --to "张三" --reply "我在忙，稍后回复你"
```

先用 `--list` 查看会话的确切名称：

```bat
python auto_reply.py --list
```

## 回复内容的写法

回复内容默认是**固定文本**，也可以插入占位符让回复更自然：

| 占位符 | 含义 | 示例 |
| --- | --- | --- |
| `{content}` | 对方发来的消息原文 | `已收到您的消息：{content}` |
| `{sender}` | 发送者昵称 | `你好 {sender}` |
| `{time}` | 当前时间 | `[{time}] 我稍后回复你` |

例如配置回复 `已收到您的消息：{content}`，对方发来「明天开会吗」，你会自动回复「已收到您的消息：明天开会吗」。

## 常用参数

| 参数 | 说明 |
| --- | --- |
| `--list` | 列出所有会话名称后退出 |
| `--check` | 环境自检，不发送任何消息 |
| `--to 名字 --reply 内容` | 直接指定一条规则，跳过交互 |
| `-c, --config 路径` | 指定规则文件（默认 `rules.json`） |
| `--interval 秒` | 轮询间隔，默认 `1.0`，不建议低于 `0.5` |
| `--cooldown 秒` | 同一联系人两次回复的最小间隔，默认 `0` 不限制 |
| `--reply-each` | 对方连发多条时逐条回复（默认合并为一条） |
| `--text-only` | 只回复文本消息，忽略图片/文件/语音 |
| `--no-restore-clipboard` | 发送后不恢复原有剪贴板内容 |
| `--dump` | 导出微信控件树到 `wechat_tree.txt`，用于排查故障 |
| `--log-level DEBUG` | 输出详细日志（同时写入 `auto_reply.log`） |

`rules.json` 也可以用记事本直接编辑（仓库里的 `rules.example.json` 是同样格式的模板）：

```json
{
  "rules": [
    { "contact": "张三", "reply": "我在忙，稍后回复你" },
    { "contact": "文件传输助手", "reply": "已收到：{content}" }
  ]
}
```

## 工作原理

程序通过 Windows 的 **UI Automation** 接口操作微信窗口，等价于用程序替你点鼠标、敲键盘，**不涉及协议破解，也不注入微信进程**：

1. 定位主窗口 `WeChatMainWndForPC`，读取左侧会话列表；
2. 双击目标会话，微信会弹出独立的聊天窗口 `ChatWnd`；
3. 轮询该窗口的消息列表，用控件的运行时 ID 判断哪些是**新消息**；
4. 命中规则时，把回复内容写入剪贴板 → 粘贴到输入框 → 回车发送。

几个有意为之的设计（也都踩过坑，改动时请留意）：

- **不回复历史消息**：监听开始时先把窗口里已有的消息记为基线，只有之后新到的消息才会触发回复。
- **同一条消息只回复一次**：处理过的消息 ID 会被一直记住（每个会话上限 500 条，超出后淘汰最旧的），即使它滚出聊天窗口再滚回来，也不会被重复回复。
- **不打断你**：使用独立聊天窗口而非共享主窗口，因此你可以正常用微信聊别的人。
- **不偷剪贴板**：发送前备份、发送后恢复。
- **消息类型靠「头像位置」判断**：对方的消息头像在左、自己的在右，系统提示与时间分隔条没有头像。刻意没用控件高度判断——那会随系统字体缩放（DPI）变化而失效。
- **会话项不能用坐标判断有效性**：微信会把「已打开独立聊天窗口」的会话项报告成 `rect=(0,0,0,0)`，但内容仍可读。早期版本据此中断遍历，导致列表里只要有一个会话被打开，它后面的会话就全部丢失。

## 开发

### 搭建环境

```bat
git clone https://github.com/unicorn-hrrct/wechat-auto-reply.git
cd wechat-auto-reply
pip install -r requirements.txt
python check_deps.py
```

### 运行测试

**不需要安装微信**，`tests/` 用 `FakeControl` / `FakeWeChat` 模拟控件，覆盖消息解析、去重、规则匹配、模板渲染、监听循环等纯逻辑：

```bat
python -m unittest discover -s tests -t .
```

真实收发消息必须在装有微信 3.9.x 的本机上运行 `python auto_reply.py` 验证。

### 调试手段

| 手段 | 用途 |
| --- | --- |
| `python auto_reply.py --check` | 区分「依赖问题」与「微信界面问题」 |
| `python auto_reply.py --dump` | 导出控件树到 `wechat_tree.txt`，定位界面差异 |
| `python auto_reply.py --log-level DEBUG` | 把详细日志写入 `auto_reply.log` |
| `python check_deps.py` | 确认依赖是否齐备 |

微信改版导致定位失败时，`--dump` 导出的控件树是排查的关键——对照 `wechat_uia.py` 里用到的 `ClassName` 和 `Name`，就能看出界面差在哪里。

### 代码导航

| 想改什么 | 看哪里 |
| --- | --- |
| 微信窗口怎么定位、消息怎么读写 | `wechat_uia.py` |

## 已知局限与待办

下面这些是当前明确的短板，也是**最欢迎贡献**的方向：

| 事项 | 说明 | 难度 |
| --- | --- | --- |
| **支持微信 4.x** | 4.x 的窗口类名与控件树和 3.9.x 完全不同，需要新增一套控件定位实现。这是**最多人需要**的一块 | ⭐⭐⭐ |
| 公众号入口无法监听 | 「订阅号」这类聚合入口双击后不产生独立聊天窗口，`open_chat` 会报错 | ⭐⭐ |
| 只能发送文本 | 不支持自动回复图片、文件、语音 | ⭐⭐ |
| 接入 AI 回复 | 目前只能回固定内容，接入大模型做智能应答是不错的扩展 | ⭐⭐ |
| 长聊天记录未充分实测 | 微信在消息很多时会卸载旧消息，此时去重记录的边界行为尚未在真机验证 | ⭐⭐ |
| 非文本消息不解析内容 | 对方发来的图片记为 `[图片]`，无法据此做更精细的判断 | ⭐ |
| 群聊无法按成员区分 | 目前只按群名匹配规则，不能实现「只回复群里某个人」 | ⭐ |

有想法建议先开个 [Issue](https://github.com/unicorn-hrrct/wechat-auto-reply/issues) 聊一聊，避免白做。

## 常见问题

**Q：提示「未找到微信主窗口」**
依次确认：微信客户端是否已启动、是否已登录进入主界面、版本是否为 3.9.x。用 `--check` 会给出更具体的判断。

**Q：我的微信是 4.x，能用吗？**
不能。微信 4.x 的界面类名和控件树与 3.9.x 完全不同，本项目只适配 3.9.x。如果你愿意推动 4.x 适配，欢迎到 [Issues](https://github.com/unicorn-hrrct/wechat-auto-reply/issues) 讨论。

**Q：提示「会话列表中找不到 XXX」**
会话名必须完全一致（包括空格和表情符号）。用 `--list` 复制准确名称。

**Q：监听中途微信重启了，程序怎么办？**
程序会自动尝试重新打开被关闭的聊天窗口。若微信完全退出，连续 5 次读取失败后程序会停止并打印统计，重启微信后重新运行即可。

**Q：回复发不出去**
检查：微信主窗口是否被最小化（UIAutomation 无法操作最小化的窗口）、聊天窗口是否被关闭。开启 `--log-level DEBUG` 会记录具体失败原因到 `auto_reply.log`。

**Q：界面定位失败，控件树和预期不一样**
运行 `python auto_reply.py --dump`，会导出 `wechat_tree.txt`，对照其中的 `ClassName` 与 `Name` 即可定位差异。把这份文件贴到 Issue 里能大幅加快排查。

## 注意事项

- 本程序用于**个人自动化**（比如不在电脑前时的自动应答），请勿用于群发、营销等骚扰行为。
- 自动化操作微信存在触发账号风控的可能，建议把 `--interval` 设在 1 秒以上，并控制回复频率。
- 程序会读取聊天窗口中的消息内容用于判断是否需要回复，这些内容只在本机处理，不会外发。
